# Tech

- Language: TypeScript (strict), ES2022, no `any` in core packages.
- App: Vite + vanilla TypeScript or a small framework (Preact) for the UI. Static build, deployable to any static host.
- Workbook I/O: SheetJS Community Edition (`xlsx` from the official CDN tarball) or ExcelJS for reading/writing cells and formulas. Pick one and wrap it behind our own `Workbook` interface so the interpreter never touches the library directly.
- VBA extraction: implement in TypeScript
  - a minimal Compound File Binary (CFB/OLE2) reader (or reuse SheetJS `cfb`),
  - the MS-OVBA compression algorithm (section 2.4.1 of the MS-OVBA spec) to decompress module streams,
  - parsing of the `dir` stream to get module names and text offsets.
- VBA language: hand-written lexer, recursive-descent parser producing an AST, tree-walking interpreter. No eval of generated JavaScript.
- Tests: Vitest. Property-based tests with fast-check for the decompressor (round-trip against a reference compressor), lexer (no crash on arbitrary input) and numeric/string built-ins.
- Fixtures: workbooks under `fixtures/` are generated by our own scripts from VBA source text, so every fixture is reproducible and contains no third-party or client data.
- Formatting: Prettier defaults; ESLint recommended + typescript-eslint.

## Correctness rules that matter
- VBA numeric semantics: Integer (16-bit) overflow raises error 6, Long is 32-bit, Double is IEEE; `\` is integer division with banker's-style operand rounding; `Mod` rounds operands; `Round()` uses banker's rounding; `CInt`/`CLng` round half to even.
- String comparison is binary by default; `Option Compare Text` switches to case-insensitive.
- Arrays: `Option Base` respected; `ReDim Preserve` only resizes the last dimension.
- 1-based `Cells(row, col)`; `Range("A1:B2")` addresses; `.Value` on a multi-cell range is a 2-D 1-based array.
- Dates are Doubles (days since 1899-12-30), matching Excel.
